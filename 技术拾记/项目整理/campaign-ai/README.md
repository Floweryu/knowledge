## 项目定位

面向营销运营的 AI Agent 平台，将自然语言需求转化为活动创建、招商、选品、优惠券、秒杀、图片、页面、报名通知及广告投放等业务操作。核心技术主线是：**语义编排、确定性执行、人工确认、状态恢复和会话评估**。

项目价值应围绕“模型如何可靠地操作真实业务系统”展开。框架名称用于说明实现方式，不能代替技术问题、设计取舍和结果证据。

## 当前实现需要明确的事实

- Main DeepAgent 是当前根图，子 Agent 由 `SUBAGENT_SPECS` 统一注册，当前共有 8 类业务子 Agent。
- 当前 Main 装配同步 `CompiledSubAgent`；不能据此宣称业务 Agent 全并行执行。
- 选品查询工具覆盖 7 条产品线；查询工具覆盖、语义报文契约覆盖、真实端到端验收是不同口径。
- Main 的业务知识通过 `/skills/` 路由加载；本次核对不再沿用上一轮“确认活动类型后注入 effective_knowledge 快照”的描述。
- Main 对稳定提示词设置条件式缓存标记，动态状态每次重建；时间文本按十分钟窗口取整。
- PostgreSQL checkpoint 负责图状态恢复；启用 Redis RunBus 时，Redis Streams 支持运行中事件回放。
- 断线后继续运行依赖原进程中的任务仍存活，不等于进程故障后自动接管。
- 选品写入有预览门禁和会话内重复创建防护；不等于强授权令牌、跨会话幂等或外部系统 Exactly-once。
- 评估有基于产物证据的任务成功判定，以及 LLM Judge；没有证据时应保留不可评估状态。
